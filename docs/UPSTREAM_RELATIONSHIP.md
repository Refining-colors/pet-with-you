核对日期：2026-09-27。上游：[PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet)，本次对比固定在提交 [631c5310](https://github.com/PC2005-cloud/dsh-pet/tree/631c5310b047931404978152fdc7865413c153ec)。这是技术来源核对，不是整个项目的原创比例或法律结论。

## 技术结论

pet-with-you 是具有独立产品定位和较多扩展的衍生项目，与上游关联强。可以使用自己的名称、仓库、维护者署名和发行版本，同时准确说明沿用的基础。

### 素材

本项目 `assets/webm` 的 106 个文件与上游同名文件全部逐字节一致。核对使用 Git blob SHA-1（包括 blob 长度头），不是仅比较名称或大小。原角色动画构成当前主要视觉形象，迁移平台、截图或提取文件不会改变它们的来源。

独立 Windows 使用流程、Codex 任务状态聚合、自有 API 服务与配置、账户/代理额度、设置界面与自动保存、错误日志、位置/启停策略及演示工具，是当前项目独立维护和发展的主要部分。与上游不同的产品形态和新增功能值得作为首页与宣传重点。

## GitHub 开发者生态

- 不存在“改动达到某百分比就可以省略来源”的社区通用规则。
- 可以建立独立仓库，不强制使用 GitHub 的 Fork 按钮；平台的仓库关系标签和代码/素材来源是不同概念。
- 使用 Fork 时 GitHub 自动显示上游关系；新建空仓库时应自行在 README 和来源文件说明关系。
- 主项目作者/维护者可以显示 Refining-colors，上游署名用于说明沿用部分，不意味着上游作者维护或背书本项目。
- 独立功能越多，介绍越应突出自己的贡献，但不应将沿用角色、动画和运行代码描述为全部原创。

上游代码 MIT 的要求是保留版权声明与许可文本，并不是要求每个页面或每帧视频显示作者。另需单独看上游对素材的非商业使用说明及 README 中的二创约定：

> 基于本项目的衍生 / 改版 / 换皮作品，在任何介绍、展示、分发该作品的地方，须附上原作者 GitHub 地址：https://github.com/PC2005-cloud/dsh-pet

这段是上游自身的约定，不是 GitHub 平台的统一规定；不在此对其具体法律效力作判断。使用现有素材发布时，不应默认为单独放本项目链接、再让读者自行寻找上游就满足该表述。

## 创建仓库时的选项

当前本地已有完整 README，创建空仓库时 **Add README 关闭、Add license 选 None、Add .gitignore 选 None**，避免生成另一套初始文件和无关提交。之后上传本地文件即可。

本项目新增代码已选择 MIT，并保留上游 MIT；素材、字体等单独说明授权范围。仓库的 MIT 标签不表示角色素材也允许商用。
