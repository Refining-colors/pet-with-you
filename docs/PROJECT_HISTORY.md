## 从哪里开始

2026-09-28 版本策略：维护者要求小修复采用更细的修订号，本次定为 `0.1.0-alpha.7.1`。本机安装版同步修复不代表 GitHub Release 已发布，公开下载入口在正式发布新安装包前仍指向 alpha.7。

2026-09-28 窗口恢复修复（未发布）：独立窗口验证复现了当前 Windows / Electron 下 `floating` 未进入真正置顶层的问题，改用 `screen-saver` 层级。针对客户端最小化、关闭重开后的遮挡，补充 Windows 实际窗口层级、可见性和最小化状态检查。检测故障会重试，且不触发“随客户端关闭”。规则只作用于已登记的宠物窗口，修正旧窗口延迟关闭影响新窗口登记的问题；独立窗口验证使用模拟前台归属与真实 Windows 层级，不操作维护者正在使用的客户端。手动隐藏和全屏隐藏仍优先，置顶修复不抢输入焦点。

项目最初来自一个想法：把 [PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet) 的蓝发角色带到当前使用的 Codex 桌面客户端。早期主要关注原生宠物适配、放大后的模糊，以及切换动作时的重绘问题。

随后需求扩展到全部动作、随机播放、手动点播、聊天、碎碎念、额度查询和多任务反馈。当前实现已发展为独立的 Windows 桌宠，并提供可选的 Codex 联动；不是把所有扩展功能直接塞进客户端原生宠物。界面中的“GPT连接设置”是产品功能名称，当前具体对接的是 Codex 桌面客户端。

项目初衷是个人使用，后来决定整理为可供他人安装的开源项目。维护者为 Refining-colors，名称最终暂定 **pet-with-you**；曾讨论过 pet-withu、pet-companion-withu 等名称。

## 功能如何逐步形成

### 第一阶段：从原生适配到完整动作

- 尝试改善原生宠物素材放大后的模糊，关注切换和重绘混乱。
- 发现吃东西、玩耍等动作需要更完整的触发入口，逐步加入手动点播和随机轮换。
- 决定优先完成玩法与功能迁移，之后再集中处理画质和美术。
- 当前保留上游 106 段动画；这些动画不是本项目重新创作的角色素材。

### 第二阶段：建立独立桌宠与客户端联动

- 形成纯桌宠和连接客户端两种模式，默认纯桌宠；纯桌宠可以独立启动、退出。
- 纯桌宠仍保留自有 API 聊天、碎碎念和密钥／代理额度查询。
- 接入本地任务记录与 Hooks，逐步展示思考、执行工具、等待确认、出错、完成等状态。
- 增加原生风格任务卡与基础动画反馈的独立开关；多任务按优先级反馈，并显示已观测的任务数量。
- 多任务文案从一行冗长说明改为“任务数量”和“当前状态”分行展示。
- 增加“关闭事件响应”，方便演示和录屏；手动聊天、手动查询仍可使用。

### 第三阶段：补齐日常交互和设置

- 增加置顶、全屏隐藏、客户端例外、底部吸附、位置记忆和禁止自主跑动。
- 调整拖动响应、动作速度和随机动作覆盖，避免拖拽及手动动作被自动播放抢占。
- 托盘菜单经历尺寸调整，最终采用 11px 字体；菜单按钮完整显示，不使用滚动条。
- 增加托盘图标隐藏与恢复、角色尺寸数值和同步滑条。
- 设置分为“基础设置”和按连接开关出现的“GPT连接设置”；同一选项卡内模块可拖动排序，拖动按钮保持普通指针。
- 普通设置改为关闭窗口时自动保存；保存到配置列表、载入、删除、清除仍是明确操作。

### 第四阶段：自有 API、额度与可排查性

- 自有 API 支持服务地址、模型、密钥与命名配置列表；连接客户端后也可继续使用自己的 API。
- 密钥／代理额度采用相近的配置布局，支持保存、载入、删除和清除；列表显示必要的配置摘要，密钥保留掩码。
- 接入 CRS 统计和部分通用 JSON 查询接口。聊天接口可用不代表余额接口一定可用，服务商差异仍需逐个适配。
- 登录账户额度逐步补充 5 小时、1 周、更新时间和可用重置次数；接口缺失字段显示未提供。
- 增加错误提示、留存日志、导出、定位和清除；可忽略不影响中转站用户的账户读取超时。
- 修复余额查询成功后仍被旧变量逻辑误报失败的问题，并补充成功气泡验证。
- 取消启动／闲置时不必要的额度弹出；仅手动查询或用户开启的新回合结束查询可以触发。历史完成记录不算新回合。

### 第五阶段：气泡、碎碎念与阅读体验

- 气泡尽量避免无意义滚动条，支持选中文字复制，统一右上角小叉关闭。
- 查询字体默认宋体，基础反馈／聊天字体也可选择；检查特殊波浪号与字体显示问题。
- 碎碎念等待文案改为“碎碎念中……”，去除“桌宠说”；采用与任务卡协调的界面样式。
- 加入流式输出、自动碎碎念的间隔和概率，以及本次运行内的碎碎念记录和完全重复拦截。
- 聊天／碎碎念和查询气泡都有停留设置；永久保留的回复与任务反馈协调显示，避免同时覆盖角色。
- 模型开始输出前的等待仍取决于所选服务，流式显示不能保证所有接口立即返回。

### 第六阶段：准备开源与安装包

- 建立独立源码目录，将日常设置、研究材料、参考视频、生成媒体和待发布代码分开。
- 作者信息改为 Refining-colors；托盘不再保留单独的原作入口；alpha.3 中“关于 pet-with-you”直接打开项目仓库，设置及文档保留来源说明。
- 补齐 README、安装手册、使用手册、排错、贡献、安全、来源许可和发布准备材料。
- 增加 Windows 安装程序、安装目录选择、可选桌面快捷方式，并使用托盘同款图标。
- 增加源码／历史敏感信息检查、打包检查、安装卸载检查和隔离开发预览。

## 几项必须记住的决定

### 最新决定：改为 Codex withu 联合启动器

2026-09-28：维护者最终取消“随 GPT 客户端启动”功能，不采用系统审计／计划任务，也不修改客户端原生宠物加载器。改为 **创建联动启动器**：首次开启连接模式询问，设置的 GPT 连接选项卡可随时创建，用户选择保存目录，生成 `Codex withu.lnk`。启动器每次同时打开客户端与桌宠，保留已有桌宠模式；随客户端关闭仍为独立开关。此决定取代下面历史记录中的“随启动开关＋GPT 联动启动”方案。

新图标以当前 Codex 蓝色图标为主体，配合原作“吃白饭”中的蓝毛小女仆姿态，通过内置 ImageGen 生成组合图，再编码为多尺寸 ICO；与普通 `pet-with-u` 图标分开。图标来源与提示词见 [联合启动器图标说明](LAUNCHER_ICON.md)。所有改动仍先保存在源码，上传前统一打包。

此轮完整单元测试、联合启动器定向回归和隔离界面验证通过；实际双击测试只启动临时测试程序，不触碰日常客户端。自选目录的启动器路径仅保存在本机，卸载只清理仍指向当前安装的入口；被用户改过目标的文件保留。

### 安装包集中更新，快捷方式缩短名称

2026-09-28：维护者要求日常先同步源码与文档、清理过时输出，上传仓库前再统一更新安装包，不在每轮修改后重打或覆盖日常安装。普通快捷方式改为 `pet-with-u`，项目／仓库／EXE 继续使用 `pet-with-you`；“GPT 联动启动”保留原名，避免混淆两种入口。现存 alpha.3 包不包含这之后的源码改动。

本轮同步了快捷方式生成、旧名卸载兼容和设置页启停说明，84 项单元测试、隔离界面验证及文档链接检查通过。清理旧 alpha.1／alpha.2 安装产物和临时部署／验证文件，保留 alpha.3 包、最新验证记录和用户数据备份；本轮未打包或安装。

随后补充首次正常打开设置的快捷方式询问，复用设置中的目录选择与图标逻辑，记住创建／跳过选择，失败可以重试；后台启动不主动询问。引导状态归入统一设置文件。88 项单元测试和隔离界面验证通过，仍未更新安装包。

### 启动联动不采用常驻检测

2026-09-28 补充评估：维护者希望保留原有 GPT 入口，勾选后由 GPT 启动自动触发桌宠。单独生成文件或放到客户端目录不能建立这种触发关系。Windows 进程创建审计事件加计划任务是可研究的替代路线，可保留原入口且无需桌宠自身常驻，但涉及系统审计、权限、客户端进程筛选和升级路径兼容，当前尚未实现，也没有修改用户系统策略。现行方案仍为显式联动快捷方式；不要将技术可行性评估写成已经支持。

维护者平时通过桌面、开始菜单和任务栏打开客户端，曾选择“不常驻后台：创建新的联动快捷方式，任务栏重新固定”。当时方案为：从 GPT 联动入口启动时读取桌宠设置，满足“连接模式＋随 GPT 启动”才启动桌宠，然后启动器退出。该开关方案已由上方最新决定取代。

原客户端入口和其他应用直接启动客户端不在这个方案的覆盖范围内。不要把这一限制解释成已支持任意入口自动跟随，也不要重新加入持续轮询。开机自启动是另一项独立设置。

此前出现过未勾选随客户端关闭但桌宠仍退出的问题。alpha.2 加入 Explorer 独立启动、退出前复核开关和客户端状态等修复；模拟启动方进程组结束的检查通过，但用户实际关闭客户端、重启电脑后的全过程仍需要真实使用确认。

2026-09-28 核对发现：维护者自用入口仍指向旧源码目录，alpha.2 尚未安装，且没有创建联动入口。这解释了“开关已勾选，但重启客户端没有桌宠”的现象。开发预览与日常安装的更新必须明确交付，不能仅启动隔离预览就视为用户已升级。

同日实际安装又发现 Windows MSIX 的 AppData 重定向：从客户端内部运行的工具与从 Explorer 独立启动的软件，即使使用相同路径文本，也可能看到不同的文件。此前仅从工具子进程执行的安装／启动测试没有覆盖这个边界。alpha.3 补充旧包缓存中桌宠设置的迁移，并从 Windows 独立启动验证；后续涉及用户数据和系统启动入口的验收应同时覆盖这两种运行环境。

### 设置集中，密钥不随分享文件走

普通设置集中到 `settings.json`，旧配置成功迁移后移至 `legacy-settings/`。真实密钥单独保存在本机加密的 `credentials.local.json`；机器相关的客户端启动目标另行保存。

分享时只分享检查过的 `settings.json`，不能发送整个数据目录；服务地址、提示词等也可能含个人内容。覆盖前退出桌宠，接收者需要填写自己的密钥并安装缺少的字体／角色资源。详见 [设置文件说明](SETTINGS.md)。
