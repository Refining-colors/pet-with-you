# 常见问题与排错

## Codex 在无关对话中询问如何处理 hook.cmd

旧版 Windows Hooks 注册命令只给脚本路径加了引号。在 PowerShell 下，这可能仅输出路径，没有执行脚本；`UserPromptSubmit` 的文本输出会进入模型上下文，导致模型突然询问如何处理该文件。Hooks 保存于 Codex 配置中，因此退出桌宠不会移除旧命令。

修复版使用显式、静默的 Windows 调用。更新后在桌宠控制台的 GPT 连接设置中重新配置连接，替换本安装目录的旧命令，然后在客户端重新授权 Hooks。若授权入口未刷新，切换对话；仍无变化时在任务结束后重启客户端。已进入旧对话历史的路径文字不会被自动删除，可新建对话验证。

暂时不需要任务联动时，可以在客户端 Hooks 管理中禁用 pet-with-you 的相关命令。不要删除整个 Hooks 配置，以免影响其他工具。参考：[官方 Hooks 输入输出说明](https://learn.chatgpt.com/docs/hooks)。

安装版先从桌宠设置的日志模块查看最近错误并导出反馈；无法启动时请同时提供 Windows 版本和 Release 版本。源码版可运行 `Check-Setup.cmd`，它只检查本机环境，不查询账户、不读取密钥内容、不调用模型。

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 双击后黑框退出 | Node.js 是否安装，项目是否完整解压 | 打开普通终端运行 `node --version`、`npm run doctor` |
| 找不到 Electron | 依赖是否安装成功 | 再运行 `Install-Pet.cmd`，保留下载错误 |
| npm/Electron 下载超时 | 当前网络能否访问 npm/Electron 下载站 | 按网络环境配置合法代理；不要随意关闭 TLS 验证或执行来历不明的安装脚本 |
| 启动后没有宠物 | 是否用了仅连接入口、宠物是否隐藏/禁用 | 运行 `Start-Pet.cmd`，托盘“显示宠物”，检查全屏隐藏设置 |
| 托盘不见了 | 是否主动隐藏托盘图标 | 右键桌宠 → 显示托盘图标 |
| 设置关不掉 | 是否有无效字段或保存失败提示 | 修正提示中的字段，勿强制结束来跳过保存 |
| 自有 API 模型不存在 | 模型 ID 是否为该服务商支持的准确名称 | 查服务商模型清单，注意套餐权限 |
| 401 / 403 | 密钥是否有效、请求头是否正确、是否有权限 | 在设置中重新填写，不要把密钥粘进公开日志 |
| URL 无法连接 / 返回 HTML | 是否误填网站首页、是否被登录页拦截 | 使用服务商文档给出的 API 地址 |
| 碎碎念正文慢 | 模型首字延迟、服务商排队、网络 | 开启流式显示，选响应快的模型；界面无法保证远端生成速度 |
| 聊天可用但余额失败 | 是否配置了单独的余额接口 | 聊天接口通常不能代替查询接口 |
| 读取 GPT 账户超时 | 中转站用户可能无需账户读取 | 用密钥/代理查询，保留“忽略账户读取超时类错误” |
| 连接开启但任务无响应 | 本地任务、最近事件、事件响应开关、任务反馈开关 | 新开一个本地 Codex 任务，分别检查会话读取与 Hooks 信任 |
| `/hooks` 提示命令不存在 | 是否在 PowerShell 中输入了它 | 优先按设置图示在客户端授权；备用终端需在 Codex 输入框输入 |
| `TERM=dumb` / `stdin is not a terminal` / 终端警告 | 终端能力或输入句柄，不一定是没有安装 CLI | 优先在客户端内授权；新版备用终端单独分配控制台，仍失败请记录完整错误并选择兼容的 codex.exe |
| 写入配置后客户端没有 Hooks 图标 | 客户端对当前对话的配置/界面未刷新 | 切换对话再切回，或新建本地对话；仍没有则在工作结束后重启客户端。授权后回桌宠点“授权后重新检查” |
| 配置已写入，自动检查未完成 | 无可用的 Codex 运行程序或状态读取失败 | 先按设置图示在客户端授权；选择兼容运行程序后重新检查，日志中保留检查错误 |
| 找不到 Codex 运行程序 | 安装渠道不同，或 PATH 未更新 | 选择真实 `codex.exe`；必要时依官方文档安装 CLI |
| 多个任务数量不对 | 统计仅包含已观测的本地任务 | 云端、远程、未生成兼容记录的对话可能缺失 |
| 旧额度突然弹出 | 是否运行了旧版本进程 | 退出桌宠后重新启动；新版无启动/周期自动查询，仅手动或已开启的回合完成触发 |
| 自启动失效 | 项目是否移动、Electron 依赖是否重新安装 | 从新位置启动，重新应用自启动和连接设置 |
| 换电脑后密钥解不开 | 密钥绑定 Windows 用户的系统加密 | 在新电脑重新填写，不要共享加密配置文件当作安装包 |

## 安装程序提示“不能打开要写入的文件”

这是 Windows 没有允许安装器写入指定文件，不是要求安装 Node.js。若图标和 `.webm` 动画都报错，不能仅凭文件名认定素材损坏；需要检查目标目录。**不要点击“忽略”继续安装**，否则可能得到缺少文件的程序。

1. 中止安装。若之前运行过桌宠，先从托盘退出；不要同时运行两个安装器。
2. 自定义目录可以使用。优先选择自己有写入权限的独立文件夹；另一个软件的安装目录可能继承特殊权限或受保护。可以先试默认目录，或在个人可写磁盘上新建桌宠目录，不要求必须装在 C 盘。
3. 若新建文件夹也失败，检查磁盘空间、写保护及 Windows 安全中心/安全软件的拦截记录。不要直接删除其他软件目录，也无需为此关闭全部防护。
4. 如果是覆盖安装，确认报错文件没有只读属性、没有被播放器或旧桌宠占用。权限确实需要管理员维护的目录应由有权限的人处理；更换可写目录通常更简单。
5. alpha.7 起在安装前检查目标主目录、资源目录及已有程序/图标/动画文件。失败会提示 Windows 错误码、具体位置，并尽量保存 `%TEMP%\pet-with-you-install-check.txt`。5 表示访问拒绝，32/33 表示占用，112 表示磁盘空间不足。检测通过不能保证之后没有新的拦截或磁盘变化。

反馈时提供版本号、是否全新安装、选择的目录、错误码，以及默认目录是否也失败。安装检测记录只含目录和系统错误码，但分享前仍可遮住用户名。这个日志由安装器生成，即使桌宠尚未装好也可以取得。

## 安装下载失败

如果 npm 包能下载、但 Electron 二进制下载长时间没有进度，或反复提示 `fetch failed`，可能是 GitHub 下载线路不稳定。先在安装窗口按 Ctrl+C 停止本次安装，再重试或检查本机网络；也可在项目目录的 PowerShell 临时使用 npmmirror 的 Electron 镜像：

```powershell
$petPreviousMirror = $env:ELECTRON_MIRROR
try {
  $env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
  npm ci --include=dev --foreground-scripts --cache .npm-cache
} finally {
  $env:ELECTRON_MIRROR = $petPreviousMirror
}
```

这只改变本次下载来源，保留安装器的文件校验，不会改成永久镜像或关闭 TLS 验证。

## 如何反馈问题

设置 → 错误日志：查看最近错误、导出日志、打开日志目录、清除日志。忽略账户超时只针对该类账户读取错误，不会吞掉 API 模型错误或所有网络错误。

反馈请包含：Windows 版本、项目版本、运行模式、操作步骤、预期和实际结果、错误编号。截图中遮住账户和私密任务标题。

结构化日志会尽量只保留安全的分类信息。原始 `desktop.log` 可能包含运行环境信息，不要整包上传个人数据目录；如果程序启动前就出错，只提供与错误直接相关的几行并自行检查隐私。

## 余额和任务正常，但 GPT 聊天或碎碎念失败

这三项使用不同通路：任务可从本机会话记录读取，额度通过账户接口读取，聊天则由单独的 Codex 运行服务创建新会话并请求模型。Hooks 已授权不保证模型请求成功；“本次尚未收到 Hook”也不等于授权失败。

1. 在 GPT连接设置确认 Hooks 的信任状态和所选 Codex 运行程序。已有本地任务反馈时，不必仅因尚未收到 Hook 就反复重新安装配置。
2. GPT 聊天使用该运行程序读取到的默认模型和服务商配置，不会自动使用客户端当前对话单独选择的模型。账户登录用户检查登录与模型权限；中转用户检查服务商、默认模型及请求接口兼容性。
3. 在桌宠手动重试一次，然后到基础设置 → 错误日志 → 导出日志。新版会区分认证、模型、参数、网络、回复中断和超时，记录安全的失败阶段、HTTP 状态及已知错误类型，不导出服务端原文、密钥或聊天内容。旧版只有 `gpt-failed` 的记录无法事后还原原因。
4. 反馈时附上桌宠版本、Codex 运行程序版本、账户登录还是中转密钥，以及新导出的错误日志。不要发送 `auth.json`、密钥文件或完整的私人配置。

仍可在连接模式下切换自有 API 进行聊天和碎碎念，任务联动继续使用客户端。不要通过关闭沙箱或反复授权来猜测性修复模型请求。

### 回复很慢或套餐模式等待超时

GPT 聊天可启用“优先快速回复”，仅为桌宠请求选择当前模型明确支持的最低推理强度（例如 none、minimal 或 low），不会改写 Codex 配置、切换模型或开启收费加速档。模型目录不可用或不包含自定义模型时回退到 low；自定义模型不支持这一参数时关闭即可跟随原配置。桌宠文字会话关闭不需要的应用、插件与多代理能力，客户端原有任务不变。减少推理通常有利于简单闲聊，但实际首字时间受模型、服务商排队和网络影响，不能保证固定秒数。

普通文本聊天逐步显示正文；开启聊天配图时等待完整 JSON 解析后再显示。碎碎念仍沿用独立的流式显示开关；文字按绘制帧合并更新，复用卡片、关闭按钮和文本节点，不另加打字机延时。推理内容不会作为正文显示或写入日志。

基础设置 → 错误日志中可查看本次启动最近一次 GPT 请求的启动、会话创建、生成开始至首字和总耗时，以及推理档位与代理方式。首字指标从开始生成计时，总耗时另包含前面的启动和创建会话。成功请求的这条摘要仅保留在内存，退出或删除日志后清除；失败请求的安全指标随错误日志保存。若这些本地准备时间很短而首字仍慢，主要等待发生在服务响应阶段。

Windows 仅开启系统代理时，1.0.1 会在启动 Codex 子进程时传递静态代理地址。已有 HTTP_PROXY、HTTPS_PROXY 或 ALL_PROXY（含小写）时优先保留，不覆盖用户代理选择；不修改 Windows 设置、客户端配置或记录代理地址。更改代理后请重新启动桌宠。当前不自动解释 PAC 脚本；仅用 PAC 的环境需为桌宠启动环境配置兼容的代理变量。`NO_PROXY` 保留已有条目并加入本机地址及可转换的系统绕过规则；Windows `<local>` 的所有无点主机、任意通配符规则无法完整映射，如有特殊内网绕过要求应显式配置代理环境变量。

等待策略为：发起生成后 55 秒没有正文则结束；收到正文后超过 20 秒没有新正文则结束；持续输出最多等待 120 秒。界面连接等待覆盖服务启动与这些阶段，不再先于正常生成截止。日志显示等待时长、首字时长（如有）、观察到的进度和重试次数。`turn/wait` 表示桌宠本地等待截止，不能当作服务端已返回 `turn/completed`。

如密钥模式可用而套餐模式超时，不能仅凭这一现象判定账户无权使用，也不能用余额读取成功证明模型生成通路正常。先确认切换后已重启桌宠，再提供新日志中的错误类别和进度。未收到正文时即使看不到推理事件，也不代表模型完全没有推理；服务端并不保证公开每个阶段。

## 目录和恢复

按 `Win + R` 输入 `%APPDATA%\pet-with-you` 可以打开个人数据目录，日志位于其 `logs/` 子目录。普通设置统一为 `settings.json`，密钥在 `credentials.local.json`。不要为了排错直接删除个人数据，先备份；也不要把包含密钥的文件发给他人。

联合启动未生效：确认点击的是 `Codex withu`，原版客户端入口不会被拦截。最新源码已移除“随 GPT 启动”开关，也没有后台启动检测；若仍看到旧开关，说明安装版尚未升级。启动器目标失效或目录移动后，请在 GPT连接设置重新创建并固定新入口。设置窗口仍显示旧 Electron 图标时，可取消固定旧图标，再固定新版入口；Windows 可能保留旧图标缓存。

重新下载源码不会清除个人设置；如果明确要恢复全新状态，应先退出桌宠，将个人数据目录改名备份，再启动。请勿在任务进行中删除客户端的 `.codex` 目录。

源码清理不会删除历史 `release/` 快照，它们作为本机备份保留并排除发布。生成测试截图在 `qa-output/`，演示输出在 `media-output/`；这两处都可在对应任务结束后清理。

## 更新后快捷方式图标变空白

alpha.7.1.1 起，安装器会刷新当前用户桌面与开始菜单中指向本次安装的普通桌宠快捷方式，并通知 Windows 更新图标缓存。新建快捷方式直接使用 EXE 内嵌图标，不依赖内部资源目录。不会修改 Codex withu 的独立图标。

若快捷方式保存在其他自定义目录，或安装目录曾被搬动，可从桌宠设置底部重新创建。任务栏固定入口仍可能保留 Windows 的旧缓存，可取消固定后重新固定新版快捷方式。不要为了恢复图标删除个人设置。
