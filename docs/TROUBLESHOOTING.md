# 常见问题与排错

安装版先从桌宠设置的日志模块查看最近错误并导出反馈；无法启动时请同时提供 Windows 版本和 Release 版本。源码版可运行 `Check-Setup.cmd`，它只检查本机环境，不查询账户、不读取密钥内容、不调用模型。

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 双击后黑框退出 | Node.js 是否安装，项目是否完整解压 | 打开普通终端运行 `node --version`、`npm run doctor` |
| 找不到 Electron | 依赖是否安装成功 | 再运行 `Install-Pet.cmd`，保留下载错误 |
| npm/Electron 下载超时 | 当前网络能否访问 npm/Electron 下载站 | 按网络环境配置合法代理；不要随意关闭 TLS 验证或执行来历不明的安装脚本 |
| 启动后没有宠物 | 是否用了仅连接入口、宠物是否隐藏/禁用 | 运行 `Start-Pet.cmd`，托盘“显示宠物”，检查全屏隐藏设置 |
| 托盘不见了 | 是否主动隐藏托盘图标 | 右键桌宠 → 显示托盘图标 |
| 设置关不掉 | 是否有无效字段或保存失败提示 | 修正提示中的字段，勿强制结束来跳过保存 |
| 自有 API 模型不存在 | 模型 ID 是否为该服务商支持的准确名称 | 查服务商模型清单，注意套餐权限 |
| 401 / 403 | 密钥是否有效、请求头是否正确、是否有权限 | 在设置中重新填写，不要把密钥粘进公开日志 |
| URL 无法连接 / 返回 HTML | 是否误填网站首页、是否被登录页拦截 | 使用服务商文档给出的 API 地址 |
| 碎碎念正文慢 | 模型首字延迟、服务商排队、网络 | 开启流式显示，选响应快的模型；界面无法保证远端生成速度 |
| 聊天可用但余额失败 | 是否配置了单独的余额接口 | 聊天接口通常不能代替查询接口 |
| 读取 GPT 账户超时 | 中转站用户可能无需账户读取 | 用密钥/代理查询，保留“忽略账户读取超时类错误” |
| 连接开启但任务无响应 | 本地任务、最近事件、事件响应开关、任务反馈开关 | 新开一个本地 Codex 任务，分别检查会话读取与 Hooks 信任 |
| `/hooks` 提示命令不存在 | 是否在 PowerShell 中输入了它 | 双击 `Review-Hooks.cmd`，在 Codex 交互界面输入 |
| `TERM=dumb` / 终端警告 | 是否从旧入口或不支持交互的面板启动 | 使用新版 `Review-Hooks.cmd` 或 Windows Terminal |
| 找不到 Codex 运行程序 | 安装渠道不同，或 PATH 未更新 | 选择真实 `codex.exe`；必要时依官方文档安装 CLI |
| 多个任务数量不对 | 统计仅包含已观测的本地任务 | 云端、远程、未生成兼容记录的对话可能缺失 |
| 旧额度突然弹出 | 是否运行了旧版本进程 | 退出桌宠后重新启动；新版无启动/周期自动查询，仅手动或已开启的回合完成触发 |
| 自启动失效 | 项目是否移动、Electron 依赖是否重新安装 | 从新位置启动，重新应用自启动和连接设置 |
| 换电脑后密钥解不开 | 密钥绑定 Windows 用户的系统加密 | 在新电脑重新填写，不要共享加密配置文件当作安装包 |

## 安装程序提示“不能打开要写入的文件”

这是 Windows 没有允许安装器写入指定文件，不是要求安装 Node.js。若图标和 `.webm` 动画都报错，不能仅凭文件名认定素材损坏；需要检查目标目录。**不要点击“忽略”继续安装**，否则可能得到缺少文件的程序。

1. 中止安装。若之前运行过桌宠，先从托盘退出；不要同时运行两个安装器。
2. 自定义目录可以使用。优先选择自己有写入权限的独立文件夹；另一个软件的安装目录可能继承特殊权限或受保护。可以先试默认目录，或在个人可写磁盘上新建桌宠目录，不要求必须装在 C 盘。
3. 若新建文件夹也失败，检查磁盘空间、写保护及 Windows 安全中心/安全软件的拦截记录。不要直接删除其他软件目录，也无需为此关闭全部防护。
4. 如果是覆盖安装，确认报错文件没有只读属性、没有被播放器或旧桌宠占用。权限确实需要管理员维护的目录应由有权限的人处理；更换可写目录通常更简单。
5. alpha.7 起在安装前检查目标主目录、资源目录及已有程序/图标/动画文件。失败会提示 Windows 错误码、具体位置，并尽量保存 `%TEMP%\pet-with-you-install-check.txt`。5 表示访问拒绝，32/33 表示占用，112 表示磁盘空间不足。检测通过不能保证之后没有新的拦截或磁盘变化。

反馈时提供版本号、是否全新安装、选择的目录、错误码，以及默认目录是否也失败。安装检测记录只含目录和系统错误码，但分享前仍可遮住用户名。这个日志由安装器生成，即使桌宠尚未装好也可以取得。

## 安装下载失败

如果 npm 包能下载、但 Electron 二进制下载长时间没有进度，或反复提示 `fetch failed`，可能是 GitHub 下载线路不稳定。先在安装窗口按 Ctrl+C 停止本次安装，再重试或检查本机网络；也可在项目目录的 PowerShell 临时使用 npmmirror 的 Electron 镜像：

```powershell
$petPreviousMirror = $env:ELECTRON_MIRROR
try {
  $env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
  npm ci --include=dev --foreground-scripts --cache .npm-cache
} finally {
  $env:ELECTRON_MIRROR = $petPreviousMirror
}
```

这只改变本次下载来源，保留安装器的文件校验，不会改成永久镜像或关闭 TLS 验证。

## 如何反馈问题

设置 → 错误日志：查看最近错误、导出日志、打开日志目录、清除日志。忽略账户超时只针对该类账户读取错误，不会吞掉 API 模型错误或所有网络错误。

反馈请包含：Windows 版本、项目版本、运行模式、操作步骤、预期和实际结果、错误编号。截图中遮住账户和私密任务标题。

结构化日志会尽量只保留安全的分类信息。原始 `desktop.log` 可能包含运行环境信息，不要整包上传个人数据目录；如果程序启动前就出错，只提供与错误直接相关的几行并自行检查隐私。

## 目录和恢复

按 `Win + R` 输入 `%APPDATA%\DSH Pet Companion` 可以打开个人数据目录。名称为升级兼容而保留。普通设置统一为 `settings.json`，密钥在 `credentials.local.json`；旧文件会迁入 `legacy-settings/` 作为回退备份。不要为了排错直接删除它们，先备份。

联合启动未生效：确认点击的是 `Codex withu`，原版客户端入口不会被拦截。最新源码已移除“随 GPT 启动”开关，也没有后台启动检测；若仍看到旧开关，说明安装版尚未升级。启动器目标失效或目录移动后，请在 GPT连接设置重新创建并固定新入口。设置窗口仍显示旧 Electron 图标时，可取消固定旧图标，再固定新版入口；Windows 可能保留旧图标缓存。

重新下载源码不会清除个人设置；如果明确要恢复全新状态，应先退出桌宠，将个人数据目录改名备份，再启动。请勿在任务进行中删除客户端的 `.codex` 目录。

源码清理不会删除历史 `release/` 快照，它们作为本机备份保留并排除发布。生成测试截图在 `qa-output/`，演示输出在 `media-output/`；这两处都可在对应任务结束后清理。
